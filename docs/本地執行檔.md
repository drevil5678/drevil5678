# 楊海分站賽：本地免安裝版

## 適合比賽的部署方式

一台現場伺服器執行本地程式，其他電腦用瀏覽器經同一個區域網路參賽。每隊兩人共用一個操作席，32 隊最多 16 場同時對弈。外部 Internet 中斷不影響已載入的程式、AI 模型與區網連線；主機故障、斷電或區域網路故障仍會影響活動，須彩排和準備備用主機。

採用**整個資料夾免安裝版**，執行檔、前端、KataGo 與模型預先放好。比賽主機不用安裝 Python、Node 或 uv，選手電腦不用安裝本程式。GPU 驅動及相容 CUDA／cuDNN 仍需依正式 KataGo binary 準備。單一 exe 雖然方便寄送，但會在啟動時解壓，模型也很大；資料夾版較容易固定版本、排查問題與替換 GPU 引擎。

## 建置平台與目前狀態

- Linux 執行檔在 Linux 上建置；Windows `.exe` 必須在 Windows x64 上建置，不能把 Linux 檔案改副檔名當成 exe。
- [登入 GitHub 後下載區網免安裝版](https://github.com/drevil5678/drevil5678/actions/workflows/windows-build.yml)：開啟最新成功紀錄，在 Artifacts 選擇 `yanghai-windows-lan-v0.2.0`，不需自行安裝 Python 或 uv。GitHub 附件解壓後，還需完整解壓內層程式 ZIP。雙擊 **Start-LAN.cmd**，登入主辦管理後即可複製／列印參賽網址，詳見 `區域網路部署.md`。
- 隨附的 KataGo v1.16.3 AVX2 CPU binary 需要相容 x86_64 CPU。小模型 **b6c96 / 128 visits 供開發與預演**，正式 GPU、模型、分析預算及 50 台現場電腦仍需驗證。
- 建置使用 `uv.lock` 及 PyInstaller 6.16.0。KataGo binary 依官方 release 的 SHA-256 驗證；舊模型的固定摘要來自第一次官方 HTTPS 取得，詳見 `BUILD-INFO.json`。

Linux 建置命令：

```bash
uv sync --locked --group build
.venv/bin/python scripts/build_portable.py
```

Windows 建置主機需先安裝 Python 3.12／3.13 與 uv，雙擊 `scripts/build-windows.cmd`，或執行：

```powershell
uv sync --locked --group build
.venv\Scripts\python.exe scripts\build_portable.py
```

建置需要下載依賴，**套件完成後比賽執行不需網路下載**。建置流程保留現有 `dist` 輸出；重建請指定新的 `--output` 路徑。現場電腦的 Windows／GPU 資訊尚未取得，不能宣稱 Windows 執行檔已在此 Linux 雲端驗證。

## 初次啟動

1. 先核對 ZIP 的 `.sha256` 摘要，再將**整個 ZIP**解壓到本機可寫入的資料夾。不要在 ZIP 預覽中直接雙擊，不要只複製 exe，也不要放在唯讀的 Program Files、網路共享磁碟或正在雲端同步的資料夾。
2. Windows 雙擊 `Start-LAN.cmd`；Linux 執行 `./YanghaiTournament --lan`。Linux 若解壓工具沒有保留執行權限，先执行以下命令：

```bash
chmod +x YanghaiTournament katago/AppRun katago/usr/bin/katago
```

3. 程式建立 `tournament.json` 與 `data/`，自動開啟主辦方的瀏覽器頁面。終端視窗顯示資料位置和監聽連接埠；不要關閉服務視窗。正常停止請按 Ctrl+C。
4. 第一次以 `data/admin-token` 的內容登入主辦管理頁，在本機安全讀取；不要把管理金鑰傳入群組、公開畫面或比賽備份匯出。
5. 在「區域網路開賽」選擇場地網卡，複製或列印參賽網址，先讓一台選手電腦連線。可向場地管理員預留主機固定 IPv4。Windows 防火牆只對活動使用的私人區域網路允許本程式；外部網路不用開放此連接埠。`0.0.0.0` 是監聽設定，不能拿來當參賽網址。
6. 確認 AI 顯示就緒，依活動部署文件檢錄、確認規則與開賽。

## 設定與 GPU 替換

`tournament.json` 的路徑相對於此設定檔所在資料夾，可使用絕對路徑。資料目錄與程式分離，更新 `_internal` 和執行檔不會重設棋局；**保留原本 tournament.json 與 data/**。

```json
{
  "host": "0.0.0.0",
  "port": 8000,
  "data_dir": "data",
  "katago_bin": "katago/katago.exe",
  "katago_model": "model/model.txt.gz",
  "katago_config": "config/analysis.cfg",
  "ai_concurrency": 1,
  "auto_backup_seconds": 600,
  "open_browser": true
}
```

上例的 binary 路徑適用 Windows；Linux 是 `katago/AppRun`。替換 GPU 版時保留官方套件要求的同目錄 DLL／動態函式庫，換入驗證過的模型，修改 binary、模型、設定檔路徑和分析並行數。保持 `reportAnalysisWinratesAs = SIDETOMOVE`，並行數與 KataGo `numAnalysisThreads` 相符。也可透過 `KATAGO_*` 和 `AI_CONCURRENCY` 環境變數覆寫引擎設定。

可先執行 `YanghaiTournament.exe --check` 或 `./YanghaiTournament --check` 做真實 AI 載入診斷，不更動賽事資料庫。加 `--no-browser` 可不自動開啟瀏覽器；`--config` 可指定另一個設定檔；`--host`／`--port` 只改本次啟動。

## 資料保護與備援

- 同一個資料目錄只能啟動一個本地伺服器；重複雙擊會停止第二個程序，不覆寫棋局。作業系統會在程序結束後自動釋放鎖，不需刪除 PID 檔。
- 連接埠若已被其他程式占用，程式會在打開賽事資料庫前停止，不會自動關閉其他程式。
- 每次重新啟動既有資料庫前，先透過 SQLite 備份 API 保存完整快照，包含 WAL 已提交資料；每 10 分鐘再自動備份。管理頁仍可隨時手動備份。
- 備份位於 `data/backups/`。結束／重啟會保存棋局並暫停，裁判核對後逐桌恢復。
- 備份留在同一台主機只能防部分操作錯誤；每輪將完成的備份檔複製到另一台主機或 USB。不要在執行中直接只複製 `tournament.sqlite3` 而忽略 WAL。
- 發行 ZIP 不包含實際賽事資料、管理金鑰或選手操作碼。主機備份仍含操作碼，須安全保管。
- 禁止同時讓舊的 Python 伺服器和執行檔指向同一個資料庫，也不要設定多個 Uvicorn worker。

正式活動前，以正式模型、16 場同時對弈和 50 台**實際現場電腦**測試；另測試交換器斷線、正常停止、主機重啟及備份還原。打包成執行檔會減少安裝差異，但不會自動改善 GPU 效能或避免硬體故障。
