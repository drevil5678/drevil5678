# 區域網路網頁版：一台主機，選手打網址加入

適用 Windows 10／11 的 Intel／AMD x64 主機。比賽程式、KataGo 與模型只放在主辦主機，其他電腦只需 Chrome 或 Edge。隨附 CPU 小模型供測試，正式模型、GPU 與場地效能仍需彩排。

## 主辦主機

1. 登入 GitHub，從本儲存庫的 Actions 開啟 **Build Windows test package** 最新成功紀錄，在 Artifacts 下載 `yanghai-windows-lan-v0.3.2`。
2. 解壓 GitHub 附件 ZIP，再完整解壓裡面的程式 ZIP。保留 `_internal`、`katago`、`model` 與 `config`；更新時保留原本的 `tournament.json` 與 `data`。
3. 將主機接上場地有線網路，或與選手共用的 Wi-Fi。双擊 **Start-LAN.cmd**。這會以區網模式啟動，即使舊設定使用 `127.0.0.1` 也能加入。
4. 程式自動開啟主辦管理頁。用記事本安全讀取 `data/admin-token`，登入後看最上方的 **區域網路開賽**。
5. 如顯示多張網卡，選擇場地的 Ethernet／Wi-Fi 網卡，不選 VPN 或其他虛擬網路。按 **複製參賽網址** 或 **列印參賽網址**，先讓一台選手電腦測試，再交給其他選手。
6. Windows 防火牆詢問時，允許本程式使用活動的私人網路。主機程式視窗保持開啟；正常停止按 Ctrl+C。

分享的參賽網址只包含主機 IPv4、連接埠與賽場入口，不含管理金鑰或點棋操作碼。列印網址的紙張與點棋操作碼分開；操作碼只交給該桌指定點棋手。

主辦提供的 18 隊已內建：空白賽事首次啟動會自動建立名單及本機固定碼，不需匯入表格。已有隊伍或棋局時會原樣保留；詳見 [18 隊快速開賽](18隊快速開賽.md)。

## 選手電腦

1. 連到與主機相同的區域網路。不要使用隔離的訪客 Wi-Fi。
2. 開啟 Chrome／Edge，輸入主辦方提供的完整網址，例如 `http://192.168.1.20:8000/#arena`。實際網址以主辦頁顯示為準。
3. 進入自己的對戰桌，輸入該桌黑／白方操作碼，等待裁判開賽。選手不用安裝 exe、Python、uv 或 AI 模型。

## 連線與賽前彩排

- 主機換網路後按 **重新檢查**；如 IP 改變，重新分享網址。請向場地管理員預留主機固定 IP／DHCP 租約，避免活動中更換。
- 主機能開但選手不能開：檢查同一區網、Windows 私人網路防火牆、Wi-Fi 訪客隔離、是否選錯 VPN 網卡。若仍失敗，先改用同一台交換器的有線網路。
- 區網網址顯示「等待場地網路」：接上場地網路後重新檢查。顯示「本機測試模式」：停止後用 `Start-LAN.cmd` 啟動。
- 依序用 1 台、2 台、最後全場 50 台電腦測試。用正式模型進行 16 桌同時對弈，確認提示延遲與時鐘；雲端模擬客戶端不能取代現場彩排。
- 測試暫停／恢復、主機重新啟動及備份還原；資料與備份位置會顯示在主辦部署區。每輪另存備份到 USB 或備用主機。

外部 Internet 中斷不影響已準備好的程式與同一區網；主機斷電或場地區網中斷仍會影響比賽。

## 指令啟動

Windows：`YanghaiTournament.exe --lan`。Linux：`./YanghaiTournament --lan`。`--lan` 只覆寫本次監聽為 `0.0.0.0`，不改寫已有賽事設定與資料。可用 `--port` 指定其他連接埠，網址顯示會同步更新。
